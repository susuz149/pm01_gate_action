## 问题 2：模型加载后机器人"特别软"，直接倒下

### 现象
运行 simulation.py 后，机器人身体软塌塌地倒下，完全站不住。

### 原因
PM01 模型使用的是 **力矩执行器（motor）**，而非位置伺服。没有施加控制力矩时，关节不受力，在重力作用下自然就软了。

### 解决方案
使用 PD 控制，根据关节目标角度和当前角度的偏差计算力矩：
```python
tau = Kp * (q_target - q_current) - Kd * q_current_vel
```

通过调节 Kp 和 Kd 增益，让关节稳定跟踪目标角度。

## 问题 3：初始姿态奇怪，右腿前迈、身体转向左

### 现象
运行 pose_tuner.py 后，机器人初始姿态不正，右腿向前伸、身体和头转向左边。

### 原因
`simulation.py` 中只对双臂做了 PD 控制，**腿部和躯干没有控制**，在重力和初始偏差下自由摆动，导致姿态歪斜。

### 解决方案
对下半身所有关节采用**硬固定**策略，每步仿真后直接重置关节角度和速度为初始值：
```python
for jid, qadr, vadr, q0 in body_joints:
    data.qpos[qadr] = q0   # 固定角度
    data.qvel[vadr] = 0.0  # 速度清零
```

这样机器人稳稳站立，只有双臂在动，方便调试上肢动作。

## 问题 4：终端日志不显示或输出混乱

### 现象
使用 `print(..., end="")` 做覆盖打印时，终端里看不到输出，或者 `\r` 回车符行为异常。

### 原因
1. Python 的 `print` 默认缓冲输出，`end=""` 时不会自动 flush
2. `\r` 覆盖打印在某些终端/环境下行为不一致
3. 只显示仿真时间，无法与真实时间对比

### 解决方案
1. 所有 `print` 加 `flush=True`，确保立即输出
2. 改为**阶段切换时打印一行**，不用覆盖模式，更清晰
3. 同时显示**真实时间 / 仿真时间**，方便验证实时性
4. 增加 V 键切换日志开关，嫌吵可以关掉

## 问题 5：左右臂姿态不对称

### 现象
手动调姿态时，左右臂分别调出来的 roll/yaw 角度不一样，动作不对称。

### 原因
手动逐个关节调试很难做到左右完全一致，而且左右臂的关节正方向是镜像的，容易搞混。

### 解决方案
**以左臂为准，右臂通过镜像公式计算**：
```
右臂 = [肩pitch不变, -肩roll, -肩yaw, 肘pitch不变, -肘yaw]
```

即 pitch 类关节左右相同，roll 和 yaw 类关节正负号相反。这样保证动作完全镜像对称。

## 问题 6：展开姿态的肘 pitch 方向与直觉相反

### 现象
从"脸前"到"展开"时，肘 pitch 从负值（-1.8）变为正值（-0.36），小臂的朝向变化与直觉不太一样。

### 原因
PM01 模型的肘 pitch 轴方向定义与常见人体解剖学方向有差异，导致动作直观感受需要适应。

### 解决方案
经过实际观察，虽然肘 pitch 方向和直觉有差异，但动作整体效果符合"双手从脸前向两侧推开"的开闸意象。因此保留当前参数，以动作观感和任务目标为准。

## 问题 7：固定基座用什么方法

### 疑问
MuJoCo 固定基座有多种方法（weld joint、equality constraint、每步重置等），哪种最好？

### 方案对比

| 方法 | 实现方式 | 物理正确性 | 稳定性 | 复杂度 |
|------|---------|:----------:|:------:|:------:|
| weld joint | 改 XML 把 freejoint 换成 weld | ✅ 高 | ✅ 高 | 低 |
| equality constraint | 加 equality 约束 | ✅ 高 | ⚠️ 中 | 中 |
| mocap body + weld | 用 mocap 体拉着 | ✅ 高 | ✅ 高 | 高 |
| **每步硬重置** | 每步直接设 qpos/qvel | ⚠️ 非物理 | ✅ 最高 | **最低** |

### 最终选择
采用**每步硬重置法**，理由：
1. 任务书明确允许固定基座，不考察平衡控制
2. 实现最简单，绝对稳定，零调试成本
3. 专注于上肢动作，下半身稳定无干扰
4. 对本任务（动作开发考核）完全够用

## 问题 8：仿真环境下 PD 参数难以评估是否会震荡

### 现象

在 MuJoCo 仿真中调整 PD 增益时发现：即使把 Kp 调到很大（比如翻倍），关节也不会出现明显震荡，很难通过视觉判断：
- PD 参数是否合适，有没有接近震荡临界
- 力矩是否足够，有没有饱和
- 参数的安全裕量有多大

### 原因

仿真环境与真实机器人有本质差异，导致 PD 控制的宽容度远高于真实系统：

1. **执行器力矩限幅**：`actuator_ctrlrange` 限制了最大输出力矩，PD 计算的力矩再大也会被裁到上限，相当于天然的"限幅安全阀"，不会因为 Kp 过大而出现正反馈震荡
2. **仿真步长小（2 ms / 500 Hz）**：数字控制系统中采样频率越高，相位裕度越大，系统越稳定，越不容易震荡。真实机器人控制频率通常 100~200 Hz，稳定性裕度小很多
3. **无非线性因素**：仿真模型没有关节摩擦、齿轮间隙、传感器噪声、线缆张力等真实机器人常见的非线性因素，而这些往往是真实系统震荡的主要诱因
4. **速度前馈**：目标速度前馈项减小了动态跟踪误差，进一步提高了系统稳定性

### 说明与建议

- 当前 PD 参数（Kp=100/80/50，Kd=4/3/2）为保守取值，留有较大余量
- 仿真中"不抖"不代表真实机器人上也"不抖"，参数迁移到真实系统时需重新调试
- 若想在仿真中评估参数极限，可尝试以下方法：
  1. **取消力矩限幅**：临时将 `actuator_ctrlrange` 改大，观察纯 PD 控制下的震荡情况
  2. **去掉 D 项**：将 KD 设为 0，观察纯比例控制的响应
  3. **增加控制延迟**：在控制回路中引入 1~2 步的延迟，模拟真实系统的通信/计算延迟
- 对本任务而言，当前参数满足动作跟踪要求即可，参数的真实有效性需在真机上进一步验证
